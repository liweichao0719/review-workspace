# 数据源格式矩阵

平台核心不提供统一的“万能文件读取器”。每个适配器在边界内完成来源解析、字段转换、
稳定排序和版本计算，再向公共 API 返回相同的最小模型。

| 来源格式 | 参考适配器 | 解析与转换 | 数据版本策略 | 契约测试 |
| --- | --- | --- | --- | --- |
| JSONL | `DemoArticleAdapter` | 逐行读取对象，保留文章专属字段 | 原文件 SHA-256 | 已通过 |
| JSON | `DemoGraphAdapter` | 读取对象数组，校验节点、关系和证据 | 原文件 SHA-256 | 已通过 |
| CSV | `DemoCsvArticleAdapter` | `DictReader` 读取；管道分隔单元格转换为列表 | 原文件 SHA-256 | 已通过 |
| SQLite | `DemoSqliteArticleAdapter` | 只读、显式列查询、按稳定 ID 排序；JSON 列转换为列表 | 规范化查询结果 SHA-256 | 已通过 |

CSV 和 SQLite 示例故意复用 `article_review` 任务结构，证明来源格式不会影响任务组件。
它们是接入模式与测试样例，不默认注册成重复的界面项目；接入真实来源时，应配置实际
路径后注册对应适配器。

SQLite 样例数据库由 `backend/fixtures/demo_articles.sqlite.sql` 在测试临时目录中生成，
仓库不保存不透明的二进制数据库。适配器本身使用只读连接，不创建或修改来源数据库。

## 公共适配器契约

`backend/tests/support/adapter_contract.py` 可以被任何新适配器复用，统一检查：

- 项目和任务描述完整，任务 ID 与状态值不重复；
- 数据版本非空、可复现，列表顺序和内容可复现；
- 列表 ID 唯一，列表标题与详情一致；
- 稳定 ID 可查询，未知任务和条目明确失败；
- 合法审核可归一化且不修改调用方补丁，非法状态会被拒绝；
- 审核记录可通过 `apply_review` 恢复，同时不污染新的原始详情对象。

格式专项测试还验证 CSV 和 SQLite 的来源内容变化会生成新版本，并检查缺列、缺表时的
错误信息。业务字段是否合法仍由具体适配器负责，不属于公共契约。
